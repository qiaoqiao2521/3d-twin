# 机械结构与行为研究分开

当前五项均可提供原始机械设计与本地展示，只有 OLSK 自带原装配步骤、点选、说明、镜头及教学图示。CAD 的几何、命名和装配关系不能自动证明运动约束、闭环控制或真实设备状态。

| 来源 | 原作可研究内容 | 当前已接入的行为 | 后续接口需要的真实依据 |
| --- | --- | --- | --- |
| OLSK Small / Large CNC | 分步装配、原 IN / OUT 模型、零件点选、说明与图示 | 原装配应用直接运行；生命周期与小屏布局由宿主适配 | 步骤选择可从原 React 状态单独适配，设备轴运动仍须控制器与原机械约束证据 |
| Voron 2.4r2 | CoreXY 机构、Z 机构、固件及配置资料 | 原整机结构查看 | 原固件配置、各轴坐标/限位与实际皮带拓扑；不能把零件树的父子关系当成传动求解 |
| Jubilee | 换工具机械结构、工具架、原装配图纸；Science Jubilee 的控制与工具类 | 原 CAD 整机展示；所有原 Python 与工具文件保留供阅读 | 原工具坐标、工具校准、真实控制器连接及设备反馈，分别以独立控制适配器研究 |

## 生命周期接口

OLSK 的宿主适配暴露 `__hardwareScenePause(hidden)` 与 `__hardwareSceneDispose()`。`hidden=true` 暂停 RAF 并释放 Pointer Capture / Pointer Lock；恢复时只调度仍待执行的帧。退出同步调用原 React root 的 `unmount()`，随后终止该文档创建的 Draco 等 Worker、释放追踪到的 WebGL context，宿主再销毁 iframe。只接受直系父窗口、同源身份的消息作为兼容入口；BFCache pagehide 暂停而不永久销毁，pageshow 按文档可见性恢复。

该接口只处理显示文档，不承担 CNC、打印机、机器人或 OPC UA 的停机逻辑。任何将来真实设备控制都必须有自己的设备会话与结果语义，不能把销毁网页等同于停止物理机器。

## OPC UA 原异常语义的独立修复

原上游控制脚本在某些异常之后仍返回成功。独立的 [OPC UA 行为适配研究](../../../research/hardware/opcua/README.md) 保留原脚本字节，并在单独适配层传播执行异常、区分操作成功与失败、清理取消状态；通过注入无硬件执行器测试。它没有启动原 OPC UA 端点，没有调用真实 GPIO，也没有与网页渲染生命周期混合。原程序原件仍在设备完整来源包中。

## 复用接口评估

显示端可以复用已固定的 `asset.json`，明确模型坐标、原件路径和能力；行为端应独立提供带来源和单位的状态，如时间戳、关节/轴名称、测量值及是否为观测。请求的动作与实际反馈必须区分，不能用动画进度伪造已到位。当前没有新增这种实机状态接口，也没有把浏览器动画称为加工、抓取或搬运验收。
